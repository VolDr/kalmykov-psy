# Клип-статьи (лид-магнит с опросником и разбором в боте)

Лид-магнит: статья, показанная короткими экранами с кнопкой «Дальше», в конце —
опросник на уровень выгорания (BAT-23). **На сайте показывается только общий
результат** (балл + зона). Подробный разбор по четырём сферам и рекомендации
выдаёт телеграм-бот после проверки подписки на канал.

Всё настраивается через админку, статей может быть сколько угодно — код на каждую
новую статью писать не нужно.

## Поток пользователя

1. `/useful/<slug>` — экраны статьи ([useful/[slug]/+page.svelte](../src/routes/useful/%5Bslug%5D/+page.svelte)),
   прогресс и текущий экран хранятся в localStorage.
2. Последний экран → опросник ([ClipQuiz.svelte](../src/lib/components/questionnaire/ClipQuiz.svelte)).
3. Финал опросника → `POST /api/quiz-results`: ответы пересчитываются **на сервере**
   ([api/quiz-results](../src/routes/api/quiz-results/+server.ts)), результат пишется
   в `quiz_results` с уникальным `token`. Возвращается общий балл/зона + диплинк
   `t.me/<бот>?start=qr_<token>`.
4. Сайт показывает общий результат + кнопку «Получить разбор в боте» (диплинк).
5. В боте `/start qr_<token>` ([telegram-client-bot.server.ts](../src/lib/server/telegram-client-bot.server.ts)):
   [quiz-bot.server.ts](../src/lib/server/quiz-bot.server.ts) проверяет подписку на
   канал; не подписан — сообщение с кнопками «Подписаться» + «Я подписался»
   (callback `qz:<token>`), подписан — сразу разбор.
6. Разбор: вступление с общим баллом, затем каждая сфера — строка с её баллом и
   зоной, под ней рекомендация по зоне (красные → оранжевые → зелёные). Завершения с CTA в разборе
   нет — призыв записаться ставится шагом цепочки `quiz_results_delivered`. Блоки склеиваются в
   сообщения по лимиту Telegram ([quiz-messages.ts](../src/lib/server/quiz-messages.ts), покрыт тестами).

## Идемпотентность

`deliverQuizResults` шлёт сообщения разбора, вешает теги и запускает цепочку
`quiz_results_delivered` **при каждой выдаче**, в том числе при повторном заходе по
ссылке, — так же, как события лид-магнитов. Чтобы повторный `/start` не начинал
прогрев сначала, у цепочки ставится кулдаун «не запускать чаще раза в N дней».
`delivered_at` хранит время первой выдачи и при повторной не меняется.

## После выдачи разбора

Контакту вешаются теги `quiz_burnout` и `quiz_burnout_<зона>` (green/orange/red…),
затем запускается включённая цепочка с триггером «Диплинк /start=» и значением
`quiz_results_delivered`, если такая настроена (для прогрева). Картинки/файлы в
самом разборе не поддерживаются — доставляйте их шагами этой цепочки
(шаги сценариев умеют файлы-вложения, см. [docs/bot.md]).

## Админка (раздел «Бот»)

- **Лид-статьи** ([clip-articles](../src/routes/admin/bot/clip-articles)) — список,
  создание, редактор: экраны (заголовок / текст / кнопка / URL картинки,
  добавить-удалить-переставить), тексты общего результата по зонам, CTA в бота.
  Экран может быть только с картинкой без текста. Разметка текста: `**жирный**`,
  `[ссылка](https://…)`.
- **Опросник** ([quiz](../src/routes/admin/bot/quiz)) — настройки бота (singleton-строка
  `quiz_bot_settings`): канал для проверки подписки, тексты просьбы подписаться,
  рекомендации по 4 сферам × 3 зоны (зелёная/оранжевая/красная; для зелёной пусто —
  ничего не отправляется, для оранжевой пусто →
  берётся красная) и вступление. Пустые поля работают на дефолтах из
  `DEFAULT_QUIZ_BOT_TEXTS` / `DEFAULT_SPHERE_RECS`.

## Опросник на статической странице (A/B-тест focus)

У лид-магнита «Вы отдохнули, а легче не стало» два варианта концовки, трафик
делится на уровне рекламы:

- `/useful/focus-attention` — вариант A, CTA на встречу-знакомство;
- `/useful/focus-attention-quiz` — вариант B, тот же лонгрид + опросник с
  разбором в боте (шаги 3–6 потока выше работают один в один).

Воронка из Директа одинаковая до самого CTA — иначе тест померит разницу
в рекламе, а не в конверсионном действии:

| | вариант A | вариант B |
|---|---|---|
| посадочная рекламы | `/ads/attention` | `/ads/attention-quiz` |
| ключ сценария в боте | `focus_ad` | `focus_quiz_ad` |
| короткая ссылка из бота | `/go/f/{contact_id}` | `/go/fq/{contact_id}` |
| концовка лонгрида | встреча-знакомство | опросник → разбор в боте |

Сценарий с ключом `focus_quiz_ad` в админке нужно завести руками — он и должен
слать кнопку со ссылкой `/go/fq/{contact_id}`.

Текст лонгрида общий — [FocusAttentionArticle.svelte](../src/lib/components/leadmagnet/FocusAttentionArticle.svelte),
страницы передают в него только свой блок CTA. Тексты результатов варианта B
лежат в самой странице, тексты бота — в админке `/admin/bot/quiz`, как у обычных
клип-статей.

Записи в `clip_articles` у варианта B нет, поэтому его слаг перечислен в
`STATIC_QUIZ_SLUGS` ([clip-articles.server.ts](../src/lib/server/clip-articles.server.ts)) —
`/api/quiz-results` принимает такие слаги без похода в БД. Слаг заодно
зарезервирован, чтобы клип-статья с тем же именем не оказалась недоступной.

## Напоминание о незабранном разборе

Человек прошёл опросник, но не нажал «Получить разбор в боте». Если он пришёл
по ссылке из бота (`/go/*`, cookie `sb_client_id`), `/api/quiz-results`
сохраняет в результате `site_contact_id` — контакт из cookie. Это не владелец:
`contact_id` по-прежнему ставится тому, кто первым забрал разбор по токену.

В цепочке `lm_<магнит>_completed` ставится кнопка
`https://t.me/kalmykov_psy_bot?start=quiz_result`. Бот ([handleQuizResultReminder](../src/lib/server/quiz-bot.server.ts))
берёт последний результат с `site_contact_id` этого контакта, который никто
другой ещё не забрал, и передаёт его токен в обычный `handleQuizDeeplink`:
шлагбаум подписки, разбор, теги, `quiz_results_delivered`. Не нашёл — отвечает,
что результатов нет.

Риск: если человек переслал свою ссылку `/go/…/{contact_id}`, разбор
получателя может уйти владельцу ссылки. Миграция:
[drizzle/0018_quiz_results_site_contact.sql](../drizzle/0018_quiz_results_site_contact.sql).

## Slug

`validateSlug` ([clip-articles.server.ts](../src/lib/server/clip-articles.server.ts)):
латиница-цифры-дефисы. Зарезервированы имена существующих статических роутов под
`/useful` (`focus-attention`, `organized-burnout`, `vacation-did-not-help`,
`burnout-questionnaire`) — статический роут в SvelteKit победил бы динамический
`[slug]`, поэтому такие slug запрещены.

## Таблицы (`src/db/schema.ts`)

- `clip_articles` — статьи; `pages` (jsonb `ClipArticlePage[]`), тексты результатов,
  CTA. `slug` уникален.
- `quiz_results` — прохождения; `token` (payload диплинка), срез по сферам в jsonb,
  `contact_id` + `delivered_at` (заполняются при выдаче в боте).
- `quiz_bot_settings` — одна строка настроек выдачи в боте.

Миграция: [drizzle/0010_clip_articles.sql](../drizzle/0010_clip_articles.sql)
(применять вручную, как остальные миграции бота).

## Цели Метрики

`clip_opened`, `clip_progress_25/50/75`, `clip_quiz_started`, `clip_quiz_completed`,
`clip_bot_results_click` — параметр `article` = slug. Подробнее: [docs/analytics.md](analytics.md).
