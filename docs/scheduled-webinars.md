# Автовебинары: готовый HLS без конвертации на VPS

В ветке wip-2 автовебинары используют **заранее подготовленные HLS-сегменты**,
а не MP4 Range. Никакого кодирования, ffmpeg или обработки видеопотока
на VPS во время вебинара нет.

## Формат загрузки

Один ZIP (до 1 ГБ в сжатом виде), внутри:
- index.m3u8 — завершенный HLS VOD playlist (#EXTM3U, #EXTINF, #EXT-X-ENDLIST)
- segment_00000.ts, segment_00001.ts, ... — видео в MPEG-TS, H.264 + AAC

Допускается одна общая папка внутри ZIP; вложенные подпапки не допускаются.
Поддерживается один вариант качества (single rendition). Master-плейлисты,
много битрейтов, AES-128, fMP4 (.m4s) и удаленные URI пока не поддерживаются.

Сегменты не должны содержать более 30 секунд видео. Продолжительность
записи: от 5 секунд до 6 часов. Максимальный размер одного сегмента — 24 МБ,
максимум 15 000 файлов и 1.5 ГБ суммарно после распаковки. Для маленького
VPS разумнее делать пакет значительно меньше 1 ГБ.

Пример создания на **своем компьютере**, если исходник уже H.264/AAC:

    mkdir webinar-hls
    cd webinar-hls
    ffmpeg -i ../input.mp4 -c copy -f hls -hls_time 6 -hls_playlist_type vod -hls_segment_filename "segment_%05d.ts" index.m3u8

Если входной файл в другом кодеке, конвертируйте **у себя**, а не на VPS:
    ffmpeg -i ../input.mp4 -c:v libx264 -preset medium -crf 25 -c:a aac -b:a 128k -f hls -hls_time 6 -hls_playlist_type vod -hls_segment_filename "segment_%05d.ts" index.m3u8

Сложите index.m3u8 и все .ts в ZIP (не добавляя исходный MP4).
Например PowerShell из каталога webinar-hls:

    Compress-Archive -Path index.m3u8,*.ts -DestinationPath ../webinar-hls.zip

## Админка и просмотр

1. В /admin/webinars создайте вебинар, указав название и дату/время.
2. Выберите подготовленный ZIP. Сайт загрузит его на диск потоковым
   запросом и проверит структуру через Python stdlib zipfile.
3. Скопируйте ссылку зрителя /webinar/<id>#key=<секрет>.
4. До начала отображается обратный отсчет.
5. С момента старта сервер отдает **динамический live HLS-плейлист**:
   доступны текущий и последние несколько сегментов, но не будущие.
6. Опоздавший подключается близко к текущему моменту. hls.js (или
   нативный HLS Safari) повторно запрашивает плейлист и сегменты.
7. По окончании записи сервер прекращает отдачу, страница показывает
   завершение. При временном сетевом сбое плеер пытается восстановиться.

Без паролей: секрет приглашения обменивается на HttpOnly cookie.
Все запросы сегментов проверяют эту cookie и расписание. Это не DRM:
зритель технически может записать экран или сохранить уже показанные
сегменты. Реальный «прямой эфир» будет слегка отставать на несколько
сегментов (обычно 6–12 секунд), чтобы избежать постоянной буферизации.

## VPS: требования

Хранилище: /root/andrei/storage/webinars при текущем PM2 cwd=/root/andrei.
При другом расположении — WEBINAR_STORAGE_DIR в .env. Каталог должен
переживать деплой и быть доступен пользователю Node. Рекомендуется бэкап.

На VPS нужен Python 3 (stdlib zipfile, обычно установлен).
**Никаких дополнительных серверных видеосервисов не требуется.**
Для просмотра через HLS.js зависимость hls.js 1.7.4 добавлена в
package.json и package-lock.json; при деплое выполните npm ci и npm run build.

Nginx должен позволять большие загрузки только в админку, с минимальным
буферизированием. Добавьте в существующий HTTPS server для kalmykov-psy.ru
(проверив текущие location и proxy):

    location ~ ^/admin/webinars/[a-f0-9]{16}/upload$ {
        client_max_body_size 1024m;
        proxy_request_buffering off;
        proxy_http_version 1.1;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 900s;
        proxy_send_timeout 900s;
    }

В Node adapter установите BODY_SIZE_LIMIT=1024M через /root/andrei/.env,
если платформа отклоняет большие PUT. Код загрузчика отдельно ограничивает
фактически полученный объем, а nginx должен блокировать большие запросы
ко всем остальным маршрутам. Проверяйте свободное место: при загрузке
ZIP и распаковке понадобится 2+ ГБ временно, на VPS с 12 ГБ диска это критично.

## Протокол и ограничения

- Playlist: /api/webinars/<id>/hls/index.m3u8
- Segment: /api/webinars/<id>/hls/<file>.ts
- Сегменты не проходят через Galene/WebRTC; их раздает SvelteKit из
  непубличного каталога (без транскодинга, но с нагрузкой на HTTP и трафик).
- HLS сам по себе не экономит исходящий трафик. Для 50+ зрителей
  рекомендуем выносить защищенную раздачу на CDN.
- Текущий вариант поддерживает одно качество, без ABR. Для нескольких
  качеств нужно добавить прием master.m3u8 и вложенных вариантов.
- Код добавлен в wip-2, но **сборка и реальный просмотр на VPS еще не подтверждены**.
  Сначала проверьте короткий 1–2-минутный HLS ZIP в двух разных браузерах.
