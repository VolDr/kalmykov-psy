# Автовебинары: MP4 и расписание

Ветка wip-2 добавляет отдельный режим автовебинаров. Он не использует Galene
для заранее записанного видео, не запускает ffmpeg во время показа и не меняет
конфигурацию существующего сервиса видеовстреч.

## Что реализовано

- Создание вебинара с названием и временем начала в /admin/webinars.
- Загрузка MP4 до 1 ГБ потоковым PUT-запросом (без чтения файла целиком в память).
- Длительность определяется браузером по MP4, сохраняется сервером вместе с
  временем начала.
- Персональная для вебинара ссылка зрителя вида /webinar/<id>#key=<секрет>.
  Секрет не входит в URL HTTP-запроса и не передается в заголовке Referer.
- Зритель обменивает ключ на HttpOnly cookie, проверяемую сервером при каждом
  запросе видео и статуса.
- Показ начинается строго по времени сервера. Опоздавшие попадают на текущую
  позицию, а не в начало. После окончания видео исчезает.
- Есть повторная синхронизация часов и попытка восстановить просмотр при сбое.
- Загрузка/раздача MP4 не тратит CPU на перекодирование, но тратит исходящий
  трафик (N зрителей × битрейт видео). Это не HLS: текущий MVP раздает MP4
  с HTTP Range, для небольших аудиторий.

## Развертывание

Хранилище размещено вне /static и Git в каталоге
/root/andrei/storage/webinars (при PM2 cwd=/root/andrei). При другом каталоге
задайте WEBINAR_STORAGE_DIR; он должен переживать деплой и быть доступен
на запись пользователю Node. Рекомендуется резервное копирование каталога.

Nginx должен пропускать большие PUT только к административному адресу, а не
ко всему публичному сайту. Пример location внутри существующего server
kalmykov-psy.ru (проверьте текущую конфигурацию до изменений):

    location ~ ^/admin/webinars/[a-f0-9]{16}/upload$ {
        client_max_body_size 1024m;
        proxy_request_buffering off;
        proxy_http_version 1.1;
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 900s;
        proxy_send_timeout 900s;
    }

На адаптере SvelteKit/Node может потребоваться выставить
BODY_SIZE_LIMIT=1024M. Это глобальный лимит, поэтому запрет больших тел
на других маршрутах должен обеспечиваться nginx/хуками безопасности.
В коде загрузчика дополнительно есть предел 1 ГБ по фактически полученным
байтам. Убедитесь, что диск располагает свободным пространством больше
размера загружаемого файла и временных файлов nginx.

Для лучшей совместимости загружайте MP4 (H.264 + AAC, moov в начале файла).
Подготовьте видео на своем компьютере, не на слабом VPS:

    ffmpeg -i input.mp4 -c:v libx264 -crf 25 -preset medium -c:a aac -b:a 128k -movflags +faststart output.mp4

После деплоя:

1. Откройте /admin/webinars и задайте время начала на 10–15 минут вперед.
2. Загрузите короткий тестовый MP4; убедитесь, что загрузка доходит до 100%.
3. Скопируйте ссылку зрителя и откройте в другом браузере.
4. Проверьте таймер, автоматическое появление записи, вход в середине
   трансляции, потерю сети и завершение.

## Безопасность и ограничения MVP

- Доступ к MP4 требует приглашения, а сервер раздает байты только между
  временем начала и временем конца. Это **не DRM** и не строгое
  предотвращение перемотки: зритель с техническими знаниями может извлечь
  видео или заранее запросить следующие байты во время трансляции.
- Аудио может требовать нажатия «Включить звук» из-за ограничений autoplay.
- Для большого количества зрителей отдавайте сегментированный HLS через CDN
  с ограничением по времени и подписью сегментов; HLS сам по себе не снижает
  исходящий трафик origin без CDN-кеширования.
- Код создан и сохранен в wip-2; успешная сборка, конфигурация nginx
  и тест с реальным видео на VPS еще не подтверждены.
