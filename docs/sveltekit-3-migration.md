# Проверка миграции на SvelteKit 3

Использован официальный `sv migrate sveltekit-3 --tasks all --confirm` (CLI 1.1.1). Для завершения на рабочем дереве с изменениями применены `--no-git-check --no-install`; установка зависимостей выполнена отдельно без подавления peer dependency checks. Прежний lockfile сохранён в материалах аудита.

Установлены SvelteKit 3.1.0, adapter-node 6.0.0, Svelte 5.57.2, Vite 8.3.5, vite-plugin-svelte 7.3.1, TypeScript 6.0.3. Superforms обновлён до 3.0.0, Formsnap до 2.1.0 для совместимости. Неиспользуемые адаптеры auto/Deno и установленный CLI shadcn удалены из зависимостей. Это также убрало транзитивный npm-пакет undici; встроенный в Node fetch обновляется вместе с Node, а не lockfile.

## Ручные пункты мигратора

- Настройки перенесены в `vite.config.ts`, TypeScript расширяет `$app/tsconfig`; импорты используют `#lib` и стандартные subpath imports.
- Переменные окружения объявлены в `src/env.ts`. Optional-интеграции сохраняют прежние проверки отсутствующего значения; поведение SEC-08 намеренно не менялось.
- `$app/stores` заменён на `$app/state`; оставшиеся `invalidateAll` заменены на `refreshAll`.
- Проверены `goto` в DateSelector, RecordTable и edit-profile: они ведут на существующие внутренние маршруты. Header только читает `page.url`, не изменяя её.
- Проверены формы с `use:enhance`: действия `?/…` относятся к текущей странице. Переход на другую страницу после успешного входа сохранён.
- `json`/`text` заменены на стандартные Response API; тела подписанных вебхуков общая защита не читает.
- Публичный origin закреплён через `paths.origin`; dev-сервер больше не публикуется в сеть через `--host` по умолчанию. Для разработки на другом origin используется dev-режим; для другого production-домена origin нужно поменять перед сборкой.
- Текстовые примеры с угловыми/фигурными скобками в админке экранированы, чтобы отображаться текстом. Типизированные ссылки пагинации сохранены как готовые внутренние URL.
- Глобальный форматтер мигратора поменял кавычки во frontmatter статей, что обнаружили существующие тесты. Эти посторонние изменения content/ и других файлов вне миграции отменены; исходное содержимое статей сохранено.

## Верификация

До изменений проходили 287 тестов. После исправлений проходят 342 теста, включая 55 новых проверок безопасности и совместимости. Production-сборка adapter-node завершилась успешно. Бронирование и подпись/сумма платежей проверяются существующими тестами; новые проверки дополнительно подтверждают сохранность исходных тел вебхуков.

Полный `svelte-check` до работы имел 69 ошибок. После работы осталось 66 ошибок и 54 предупреждения; новых диагностик по сравнению с базой нет. Результат и сравнение с базой записаны в `outputs/security-audit-2026-10-25/check-comparison.json`; ранее существовавшие ошибки вне исправлений не маскируются. Незавершённые ошибки типов не следует считать успешным полным typecheck.

Результат сборки и тестов не является проверкой работающего VPS. Перед развёртыванием обязательна новая SQL-миграция; порядок описан в `docs/security-deployment.md`.
