# Видеовстречи Galene — `kalmykov-psy`

## Архитектура

- Админка сайта: `/admin/meetings`. Создание комнат, одна общая ссылка, перевыпуск доступа, удаление.
- Видеоклиент: `/meet/abc-defg-hij`. Одна ссылка для всех, без пароля. Имя вводится перед входом и сохраняется в `localStorage`. Участник с действующей сессией входа в админку сайта получает права ведущего; остальные — права участника.
- Galene: отдельный Go-бинарник на том же российском VPS, за nginx `https://meet.kalmykov-psy.ru`.
- Только сервер SvelteKit обращается к Galene Admin API по `http://127.0.0.1:8443/galene-api/v0/`.
- Браузер никогда не получает административные учетные данные. Публичный nginx должен блокировать `/galene-api/`.

**Не нужно создавать комнаты вручную в JSON!** Галене должен быть запущен и иметь `writableGroups: true`; комнаты создаются в админке.

## 1. Установка бинарника и статических файлов

Бинарник `/opt/galene/galene` уже скопирован на `box-758667`. Проверка: `/opt/galene/galene -help`. Go на VPS не нужен.

Если `/opt/galene/static` еще отсутствует, можно получить только статические файлы без сборки:

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/jech/galene.git /tmp/galene-source
git -C /tmp/galene-source sparse-checkout set static
mkdir -p /opt/galene/static
cp -a /tmp/galene-source/static/. /opt/galene/static/
```

## 2. Администратор Galene и запись комнат

Перед изменением существующей конфигурации сохраните резервную копию `/opt/galene/data/config.json`, если она уже есть.

Создайте локального пользователя процесса и каталоги:

```bash
id galene >/dev/null 2>&1 || useradd --system --home /opt/galene --shell /usr/sbin/nologin galene
mkdir -p /opt/galene/{data,groups,static}
```

Выполните Python-скрипт на VPS (пароль запрашивается интерактивно и **не попадает в историю команд**):

```bash
python3 - <<'PY'
from pathlib import Path
import getpass, hashlib, json, secrets, os
path = Path('/opt/galene/data/config.json')
cfg = json.loads(path.read_text()) if path.exists() else {}
password = getpass.getpass('Служебный пароль Galene Admin API: ')
if len(password) < 24:
    raise SystemExit('Нужен надежный пароль не короче 24 символов')
salt = secrets.token_bytes(16)
key = hashlib.pbkdf2_hmac('sha256', password.encode(), salt, 200000)
users = cfg.get('users', {})
users['site-api'] = {
    'password': {
        'type': 'pbkdf2', 'hash': 'sha-256', 'key': key.hex(),
        'salt': salt.hex(), 'iterations': 200000
    },
    'permissions': 'admin'
}
cfg['users'] = users
cfg['writableGroups'] = True
cfg['proxyURL'] = 'https://meet.kalmykov-psy.ru/'
cfg['allowOrigin'] = ['https://kalmykov-psy.ru', 'https://www.kalmykov-psy.ru']
path.write_text(json.dumps(cfg, ensure_ascii=False, indent=2))
os.chmod(path, 0o600)
print('Логин для сайта: site-api. Сохраните пароль в защищенном хранилище.')
PY
chown -R galene:galene /opt/galene
```

На SvelteKit-сервере в закрытой конфигурации PM2/окружении приложения, **не в Git**, задайте:

```dotenv
GALENE_ADMIN_URL=http://127.0.0.1:8443/
GALENE_ADMIN_USER=site-api
GALENE_ADMIN_PASSWORD=<тот_же_секрет_из_шага_2>
PUBLIC_GALENE_ORIGIN=https://meet.kalmykov-psy.ru
```

Не записывайте пароль в исходники, публичные конфиги, логи или в оболочку через `export ...` (команда может сохраниться в истории). Обновите окружение PM2 при следующем деплое через существующий механизм конфигурации сайта.

## 3. systemd

```ini
# /etc/systemd/system/galene.service
[Unit]
Description=Galene video conferencing
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=galene
Group=galene
WorkingDirectory=/opt/galene
ExecStart=/opt/galene/galene -insecure -http 127.0.0.1:8443 -turn :1194 -udp-range 50000
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now galene
systemctl status galene --no-pager
curl --max-time 5 http://127.0.0.1:8443/galene-api/v0/.groups/
```

Без Basic-авторизации последний запрос должен получить 401/403 (а не список комнат); если ответ 200 — проверьте защиту API.

## 4. nginx / HTTPS

Создайте отдельный `server` для `meet.kalmykov-psy.ru` с валидным Let's Encrypt сертификатом. Не меняйте конфигурацию основного сайта. После установки DNS и сертификата добавьте в HTTPS-блок:

```nginx
location ^~ /galene-api/ { return 404; }

location / {
    proxy_pass http://127.0.0.1:8443;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

Затем `nginx -t` и только при успешной проверке `systemctl reload nginx`.
Разрешите в файрволе и на стороне провайдера TCP 443, TCP/UDP 1194 (TURN) и UDP 50000 (медиа). Реальные маршруты/порты нужно проверить при двухстороннем звонке.

## Клиент Galene: получение статуса комнаты и CORS

У Galene `/group/<room>/.status` нет `Access-Control-Allow-Origin` при запросе с другого сайта: настройка `allowOrigin` используется для WebSocket, но не добавляет CORS к этому HTTP-ответу. Поэтому клиент `/meet` запрашивает только свой origin:

```text
GET https://kalmykov-psy.ru/api/meet/status?room=meet-...
```

SvelteKit на том же VPS запрашивает `http://127.0.0.1:8443/group/<room>/.status` по localhost и возвращает статус браузеру. Секреты управления Galene не используются для этого запроса и не покидают сервер. Возвращенный Galene `wss://meet.kalmykov-psy.ru/ws` используется браузером для WebSocket (для этого нужен корректный `allowOrigin`).

После деплоя проверьте в DevTools, что статус идет в `/api/meet/status`, а не непосредственно на поддомен Galene.

## 5. Управление комнатами

Откройте `/admin/meetings`. Действия из существующей авторизованной админки:

- Создать приватную комнату с лимитом участников 2–12.
- Получить **одну ссылку на комнату**. Вместимость определяется лимитом участников 2–12, а не числом ссылок.
- Скопировать одну ссылку для ведущего и гостей. При нажатии «Присоединиться» браузер запрашивает `/api/meet/join` — сервер проверяет действующую сессию сайта и выдает соответствующий Galene-токен. Токены не попадают в URL и SSR-данные страницы.
- Срок действия приглашений — 30 дней с момента создания или перевыпуска.
- Перевыпустить одну ссылку: старые токены отзываются, старые парольные учетные записи ведущего и гостя удаляются. Это позволяет перевести старую комнату на единый вход.
- Удалить комнату с подтверждением.

Группа Galene создается через официальный management API; новые комнаты не имеют парольных учетных записей. Токены хранятся в Galene, а их соответствие единому короткому коду — в закрытом `storage/meet-invites.json` на сервере сайта. Гость никогда не получает токен ведущего. **Пересылаемый URL является ключом доступа:** его нельзя публиковать или отправлять посторонним.

**Текущий статус:** код приглашений без пароля есть в `wip-2`, но после изменения клиент и создание токенов еще не прошли реальную проверку с двумя участниками. На VPS подтверждались запуск Galene, HTTPS при запросе с `--resolve` и локальный Admin API. Не используйте для конфиденциальных консультаций до проверки.


## Миграция уже созданной комнаты

Комната с названием формата meet-xxxxxxxxxxxxxxxx, которая создавалась по старой версии приложения, может содержать парольные учетные записи. Если секреты оказались на скриншоте или в переписке, **не используйте старые пароли**.

1. Разверните новую ветку `wip-2` на VPS обычным процессом деплоя.
2. Откройте `/admin/meetings`.
3. В карточке старой комнаты нажмите **«Создать одну ссылку и отключить старые пароли»**.
4. Проверьте, что выводится **одна ссылка** вида `/meet/abc-defg-hij`. Ведущий входит по ней же, но уже авторизован в админке сайта. Старые `host` и `wildcard-user` учетные записи удаляются через API.
5. Для полного прекращения активного сеанса при подозрении на компрометацию сначала завершите текущие соединения или удалите комнату.

Новые ссылки создаются через `POST /galene-api/v0/.groups/<room>/.tokens/`, где Galene генерирует токен. В новых токенах фиксируются права `op/present` либо `present` и срок действия, но **не имя** — его человек вводит сам. Браузер вызывает `ServerConnection.join(..., { type: 'token', token })`.

Короткий код в URL — секрет доступа гостя по предъявлению, без проверки личности. Права ведущего отдельно подтверждаются активной сессией сайта. При утечке кода перевыпустите ссылку.

## Поднятие руки и инструменты ведущего (Svelte)

- Кнопка с ладонью в нижней панели переключает поднятую руку.
  Используется **штатный Galene** `userAction('setdata', ownId, {raisehand:true/null, raisedAt: timestamp/null})`.
  Состояние и метка времени передаются всем участникам, включая вновь
  присоединившихся. Видеоплитки с поднятой рукой располагаются в начале,
  а на них и в списке людей отображается номер в очереди. При новой руке
  участникам воспроизводится короткий сигнал через Web Audio (браузер может
  блокировать его до первого взаимодействия со страницей).
  Порядок основан на клиентских часах, поэтому при большой разнице времени
  между устройствами нумерация может отличаться от фактического порядка.
- Кнопка количества участников в верхней панели открывает список.
  У ведущего рядом с гостями есть исключение из комнаты (kick); клиент
  передает `userAction('kick', id)` после подтверждения.
- Рядом с каждым гостем ведущий также видит кнопку выключения микрофона.
  Вызывается `userMessage('mute', guestId)`. Получатель обрабатывает
  **только привилегированное** сообщение, выключая аудиодорожки
  `localStream` и `displayStream`, и обновляя кнопку микрофона.
  Включить микрофон обратно может только сам пользователь.
- В верхней панели ведущий видит «Открыта» / «Закрыта». Кнопка отправляет
  `groupAction('lock')` / `groupAction('unlock')`; статус выводится
  из обновления `joined(change).status.locked`, поступающего от Galene.
  Уже подключенные продолжают разговор, новые **гости** не входят.
  Ведущий с действующими правами `op` может зайти даже в закрытую комнату
  и открыть ее. Гости видят надпись «Вход закрыт».
- Ведущему доступны удаление отдельного сообщения и очистка чата
  целиком через `groupAction('clearchat', {id,userId})` или без параметров.
  Удаление рассылается всем подключенным клиентам сообщением
  `usermessage(clearchat)`, поэтому интерфейс обновляется у всех.
- Метка роли «Ведущий» отображается только пользователю с правом `op`.
  У гостей нет надписи «Участник» в шапке.
- При исключении Galene присылает `usermessage(kicked)` и закрывает
  WebSocket. Svelte-клиент немедленно выключает входящие и исходящие медиа,
  отображает экран «Вы исключены» и записывает локальный запрет повторного
  входа с этой ссылкой в `localStorage`. Дополнительно обрабатывается
  причина закрытия WebSocket, если серверное сообщение не дошло.
- **Ограничения:** штатный протокол разрешает `setdata` только для
  собственного пользователя; ведущий не может опустить чужую руку этой
  командой. **Kick — не серверный бан:** при одной общей гостевой
  учетной записи другой браузер или очистка `localStorage` позволят
  снова войти по той же ссылке. Для надежного отзыва доступа нужны
  индивидуальные гостевые токены и серверная их отмена, либо отзыв
  общей ссылки (затронет всех приглашенных гостей).


### Проверка после деплоя

1. Откройте комнату как ведущий и как два гостя в разных браузерах.
2. Гость Б поднимает руку, затем гость А: видео Б должно быть впереди
   видео А, в плитках и списке — номера 1 и 2. Ведущий должен услышать сигнал.
3. Гость Б опускает руку: гость А становится первым; после повторного
   поднятия руки Б снова идет вторым. Проверьте оповещения на гостевых устройствах.
4. Ведущий исключает гостя А: у гостя А немедленно исчезает конференция,
   прекращается воспроизведение чужих видео/аудио, появляется экран исключения.
   После перезагрузки страницы в том же браузере вход по ссылке не предлагается.
5. Проверьте, что новый браузер по-прежнему может открыть общую ссылку;
   это **ожидаемое ограничение** без персональных отзываемых токенов.

## Известные особенности Svelte-клиента

- В комнате отображаются имена всех подключенных участников, даже если медиапоток пока не пришел; вместо видео выводится состояние подключения.
- Для участников, подключившихся после первого, клиент повторяет запрос входящих дорожек Galene. Отправка локальных дорожек использует `sendonly` transceiver, как в эталонном клиенте Galene.
- Ошибка медиа может быть связана с ICE/TURN/UDP-портами, даже если WebSocket и авторизация работают. Проверяйте двусторонний звонок с двух устройств после каждого деплоя; отсутствие второй картинки пока не доказано исправленным.
- В Svelte-клиенте подключен Longpipe с тремя режимами: выключено, легкое (0.2), сильное (0.5). Выбор доступен до входа и во время разговора и запоминается браузером. Модели загружаются на устройство с CDN Longpipe, видеопоток остается на устройстве; инструкции по CSP — `galene-background-blur.md`.
